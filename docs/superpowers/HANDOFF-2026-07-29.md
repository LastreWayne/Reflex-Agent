## 3. Qué se hizo en esta sesión

El playground se leía como un bot de notificaciones. El diagnóstico no era estético: la UI estaba organizada por flujo de datos, así que un `map()` sobre eventos crudos y un juicio recibían el mismo tratamiento visual — y las acciones que el agente **descartó** no se mostraban en ningún lado. Sin las alternativas, el agente es indistinguible de un `switch (ruleId)`.

Se construyó **el expediente**: la decisión dejó de ser una tarjeta en un carril y pasó a ser el clímax de un relato de tres actos.

- **Acto I** — carriles 1, 2, 3 (eventos, intervalos, detecciones), como estaban.
- **Acto II** — las etapas 4 y 5 **comparten un solo escenario**: el embudo, el caso, **la boleta** (las tres acciones del dominio, la elegida encendida con su motivo y el mensaje que lee una persona, las descartadas en gris con su porqué), el contrafáctico, y la consecuencia aterrizando.
- **Acto III** — recién al pie aparece la invitación a los cinco carriles. El selector de vista salió de la barra de mando: una página que ofrece el índice antes del primer capítulo se lee como un visor de datos, no como un relato.

### La decisión de diseño que sostiene todo

**`Deliberation` viaja SEPARADA de `Decision`.**

```ts
export interface Decision { actionId: string; reason: string; message: string }
export interface Deliberation {
  rejected: { actionId: string; reason: string }[]
  wouldChangeIf: string
}
export interface Verdict { decision: Decision; deliberation: Deliberation }
export type Decider = (detection, config) => Promise<Verdict>
```

Los executors siguen recibiendo `Decision` y nada más. Consecuencia: **el texto deliberativo del modelo no tiene ningún camino hasta un issue de GitHub ni un canal de Discord** — no por un filtro que alguien tenga que acordarse de mantener, sino porque no existe la ruta. Si alguien ensancha lo que llega a `/api/execute`, rompe esa garantía.

### La exhaustividad la impone el schema, no el prompt

`buildTools` genera **una tool por acción**, así que el `input_schema` de cada una sabe quiénes son las otras dos y las pide en `required` con `additionalProperties: false`. Bajo `strict: true` **el modelo no puede omitir una alternativa**. No hay instrucción en el prompt que se pueda ignorar.

## 6. Trampas que hacen perder tiempo

**El compilador tapa menos de lo que parece.** `app/api/decide/route.ts` hace `const x = await decider(...)` sin anotar el tipo, y `Response.json` acepta cualquier cosa. Durante la construcción la ruta emitió la forma equivocada (doble anidada) **sin un solo error de `tsc`**. Si tocás formas de respuesta, verificá con un test que lea el body, no con el type-checker.

**Los defectos visuales sobreviven la review automatizada.** Doce tasks pasaron limpias y dos bugs llegaron al build: el expediente se veía durante los carriles 1-3 (había `data-visible` y **cero** reglas de CSS para `.escenario`), y el visor ofrecía un paso que no cambiaba nada. Los encontró el humano mirando. **Al revisar CSS, verificá las dos direcciones**: que cada selector tenga un atributo real, *y* que cada atributo de estado tenga una regla.

**No adivines contra una captura.** El layout de los cinco carriles llevó cuatro intentos; tres fueron mirar una foto y suponer qué desbordaba, y uno de esos rompió algo que ya andaba. El instrumento es `docs/design/medir.mjs` — leé el DOM.

**La mascota no se puede desmontar.** Vive en **un** solo lugar del marcado y se reposiciona por CSS. Moverla adentro del ternario de vista reinicia su `useEffect` y la luz pega un salto visible. Hay un comentario en el sitio de render explicándolo; no lo borres.

**Nunca `git commit --amend`.** Un implementador enmendó el commit del controller y enterró un fix de seguridad bajo un mensaje `docs(plan)`.
